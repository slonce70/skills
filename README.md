# Autopilot

[![skills.sh](https://skills.sh/b/slonce70/skills)](https://skills.sh/slonce70/skills)

**Расскажи словами, что нужно построить — получи готовый проект.**

Autopilot — это навык (skill) для AI-агентов вроде Claude Code. Он берёт вашу идею, превращает её в пронумерованный список требований, при необходимости задаёт вопросы, а дальше сам пишет спецификацию, разбивает работу на таски и собирает проект целиком — с дашбордом, на котором видно, что происходит. Вам не нужно читать спецификации, оценивать задачи или разбираться в коде.

Навык самодостаточен: все правила лежат внутри него (`SKILL.md` + `phases/`), ставить другие навыки не нужно.

## Установка

Скопируйте строку в терминал.

```bash
npx skills add slonce70/skills
```

Установщик спросит, какие навыки поставить и для каких агентов — просто подтвердите.

<details>
<summary>Установка одной командой, без вопросов</summary>

```bash
npx skills add slonce70/skills --skill autopilot -a claude-code -g -y
```

| Флаг | Что делает |
|------|------------|
| `--skill autopilot` | Ставит только Autopilot |
| `-a claude-code` | Ставит для Claude Code |
| `-g` | Глобально — навык доступен во всех проектах |
| `-y` | Не задавать вопросов |

Без `-g` навык встанет только в текущую папку проекта.

</details>

**Требуется:** установленный [Node.js](https://nodejs.org) (для `npx`) и любой поддерживаемый AI-агент — Claude Code, Cursor, Codex и [70+ других](https://github.com/vercel-labs/skills#supported-agents).

## Как пользоваться

Откройте агента в папке будущего проекта и напишите:

```
/autopilot Хочу телеграм-бота, который принимает заявки на ремонт техники
и складывает их в Google-таблицу
```

Или просто опишите задачу своими словами — агент сам поймёт, что пора включить Autopilot:

> Собери мне под ключ сайт-визитку для студии маникюра, не задавай лишних вопросов

В начале агент скажет, в каком режиме работает и как его переключить, откроет дашборд — и полетит. Всё остальное произойдёт без вас.

## Режимы

После `/autopilot` можно дописать два необязательных слова: **режим** — сколько вопросов задают вам, и **глубину** — сколько прорабатывают за вас. Они независимы, порядок не важен: `/autopilot full deep интернет-магазин керамики`.

| Режим | Как включить | Что спрашивают у вас |
|---|---|---|
| **Полный автомат** | `/autopilot full ...` или «полный автомат» | Ничего. Агент решает всё сам и в конце показывает список решений, принятых за вас |
| **Полуавтомат** *(по умолчанию)* | ничего дописывать не нужно | Только развилки, которые задача действительно оставила открытыми — иногда ни одной |
| **Интервью** | `/autopilot interview ...`, «погриль меня», «задай все вопросы» | Агент разбирает задачу с вами вопрос за вопросом — а собирает потом всё сам |
| **Ручной** | `/autopilot manual ...` или «ручной режим» | Те же вопросы, плюс ваше «ок» на спецификацию и на список тасков |

| Глубина | Как включить | Что меняет |
|---|---|---|
| **Строго по брифу** | `/autopilot strict ...`, «только то, что сказал» | Ничего сверх сказанного: ни новых возможностей, ни «пока я тут, добавлю» |
| **Обычная** *(по умолчанию)* | ничего дописывать не нужно | Агент дорабатывает то, что очевидно нужно фиче, без фанатизма |
| **Максимальная** | `/autopilot deep ...`, «продумай за меня» | Каждое требование продумывается до конца, плюс проверка самой идеи на прочность |

| Доводка | Как включить | Что меняет |
|---|---|---|
| **Выключена** *(по умолчанию)* | ничего дописывать не нужно | сборка заканчивается приёмкой и отчётом |
| **«Вылижи до эталона»** | `/autopilot polish ...`, «вылижи», «доведи до идеала» | после приёмки — до трёх кругов сравнения работающего проекта с вашим эталоном и починки различий; дольше и дороже |

Режим, глубину и доводку можно поменять по ходу — просто скажите «переключись в ручной» или «поменьше отсебятины». Применится со следующего этапа.

**Что не меняется ни в одном режиме:** агент всё равно спросит вас перед необратимым — публикацией сайта, оплатой, рассылкой, удалением данных.

## Как это работает

Главный принцип: **порядок и есть продукт**. Код пишется на предпоследнем этапе; всё до него решает, *что* строить, всё после — доказывает, что построено то самое.

Второй принцип: **бриф — это контракт**. Ваши слова становятся пронумерованным списком требований до того, как случится что-либо ещё, и каждый этап сверяется с этим списком. Требование не может молча исчезнуть по дороге — это и ломает обычный вайбкодинг.

Этапы, как они видны на дашборде:

| Этап | Что происходит |
|---|---|
| **Подготовка** | git, структура `.autopilot/`, дашборд открыт |
| **Требования** | ваши слова → нумерованный манифест R01…Rnn; оригинал брифа сохраняется дословно |
| **Брифинг** | вопросы (сколько — решает режим); ответы записываются в манифест |
| **Спецификация** | что строим и что осознанно **не** строим; неизвестное помечается `PLACEHOLDER`, решения полного автомата — `ASSUMPTION` |
| **План** | спецификация → таски; каждое требование обязано попасть хотя бы в один таск |
| **Разработка** | один таск = один отдельный агент с чистой памятью = один коммит; после каждого таска — строка отчёта простым языком |
| **Код-ревью** | готовый код сверяется со спецификацией и стандартами; найденное превращается в таски-исправления и проходит ту же машину |
| **Приёмка** | слепая проверка против вашего исходного брифа (спецификацию проверяющему не показывают) и финальный отчёт на вашем языке |

Между этапами стоят ворота: манифест сверяется целиком, и проваленные ворота возвращают этап на доработку — это проверки против ваших собственных слов, и ни один режим их не отключает.

Попутно агент ведёт память проекта (`AGENTS.md` / `CLAUDE.md`) и записывает важные решения в `docs/adr/` — в следующих сессиях любому агенту не придётся выяснять всё заново.

### Дашборд

С первого этапа в `.autopilot/dashboard.html` живёт дашборд: восемь этапов, где сейчас находится сборка, какой таск в работе, сколько времени идёт прогон. Он обновляется сам — держите вкладку открытой.

### Что остаётся после прогона

```
.autopilot/
├── <имя-фичи>/
│   ├── 2026-01-15-brief.md   ваши слова, дословно — больше не редактируется
│   ├── manifest.md           требования и их статусы
│   ├── spec.md               спецификация
│   ├── interfaces.md         границы между тасками
│   └── tickets/              таски
├── state.js                  состояние прогона
└── dashboard.html            дашборд

AGENTS.md / CLAUDE.md         память проекта
docs/adr/                     решения, которые переживут прогон
```

`.autopilot/` коммитится: это ваша запись того, что было обещано и что сделано. Прогон, после которого там пусто, — не прогон.

## Когда использовать, а когда нет

**Подходит, если:**

- вы описываете, что нужно, и ждёте готовый результат, а не совместную работу над процессом;
- вы не программист и не будете читать спецификации, оценивать задачи или проверять код;
- формулировки вроде «собери под ключ», «just build it», «не задавай лишних вопросов»;
- вы хотите разобрать задачу вопросами, а собрать без вас — это режим интервью;
- вы хотите утвердить техзадание и список тасков, но не возиться с процессом — это ручной режим.

**Не подходит, если:**

| Ситуация | Что делать вместо |
|---|---|
| Хотите писать код вместе, строчка за строчкой | Работайте с агентом напрямую, без Autopilot |
| Задача — правка в одном файле | Просто попросите агента её сделать |
| Идея огромная и туманная, конечная цель неясна | Сначала определитесь с целью, потом возвращайтесь сюда |

## Ключи, пароли и доступы

Autopilot **никогда не спрашивает у вас ключи, токены и пароли** — только то, каким сервисом вы хотите пользоваться и есть ли у вас там аккаунт.

Как это работает на практике:

- вопрос будет «принимаем оплату через Stripe или ЮKassa?», а не «пришлите секретный ключ»;
- в коде появится имя переменной — `STRIPE_SECRET_KEY`, а само значение вы вписываете в файл `.env` своими руками;
- `.env` сразу попадает в `.gitignore`, чтобы ключи не ушли в историю проекта;
- в финальном отчёте будет список переменных, которые осталось заполнить — именами, без значений.

Если вы всё-таки пришлёте ключ в чат, агент вырежет его ещё до записи в файлы и предупредит вас. Ключ, случайно попавший в код или коммит, — повод его отозвать и выпустить новый.

## Чего Autopilot не делает никогда

Это встроенные ограничения — агент не имеет права их обойти:

- не пишет код до того, как появились спецификация и таски;
- не выдумывает факты о вашем бизнесе — всё неизвестное помечается как `PLACEHOLDER`, а решения полного автомата записываются как `ASSUMPTION`;
- не даёт требованию молча исчезнуть — манифест сверяется на каждых воротах;
- не просит вас проверять таски, их размер или код, кроме явных согласований в ручном режиме;
- не запускает два таска в одной памяти агента;
- не оставляет оплату, доступы и хостинг на финиш — только на старт;
- не просит и не сохраняет ваши ключи и пароли.

## Обновление и удаление

```bash
# обновить до последней версии
npx skills upgrade autopilot

# то же самое другим словом
npx skills update autopilot

# посмотреть, что установлено
npx skills list

# удалить
npx skills remove autopilot
```

Команду нужно запускать в папке того проекта, где стоит навык. Если он ставился глобально (с флагом `-g`), добавьте этот флаг и при обновлении: `npx skills upgrade autopilot -g`.

Обновление берёт свежую версию из репозитория на GitHub, поэтому достаточно одной команды — заново устанавливать навык не нужно. Чтобы агент увидел новую версию, перезапустите сессию: навыки читаются при старте.

## Что внутри репозитория

```
skills/
└── autopilot/
    ├── SKILL.md    ← оркестратор: режимы, порядок этапов, ворота

└── autopilot       ← симлинк на skills/autopilot, чтобы навык был доступен при работе в этом репо
```

Навык — это обычные markdown-файлы с инструкциями. Их можно открыть и прочитать: начните с [skills/autopilot/SKILL.md](skills/autopilot/SKILL.md).
